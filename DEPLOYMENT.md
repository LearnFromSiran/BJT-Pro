⚠️ **Back this keystore up in a password manager / secure vault.**
If you lose it you can **never** publish an update to the same app listing.
**Never commit it to git or share it publicly.**

> Recommendation: enrol in **Google Play App Signing** when you create the
> app. Google then holds the *app signing key*, and this keystore becomes your
> *upload key* (which can be reset if lost). The AAB you have is already signed
> with this upload key.

## 4. Publishing to Google Play (manual)

1. Create a [Google Play Developer account](https://play.google.com/console) ($25 one-time).
2. **Create app** → name "BJT Pro", default language, App, Free.
3. Complete the required declarations (privacy policy URL, data safety,
   content rating, target audience, ads = none).
4. **Release → Testing → Internal testing → Create release.**
5. Enable **Play App Signing** (recommended) when prompted.
6. Upload `BJT-Pro-v1.0.0.aab`.
7. Add release notes, review, and **roll out**.
8. Add testers (email list) → share the opt-in link.
9. When ready, promote the release to **Production**.

Store listing assets you'll still need to supply:
- Feature graphic (1024×500)
- At least 2 phone screenshots
- Short (80 char) & full (4000 char) descriptions
- App category & contact email

## 5. Rebuilding locally (reproducing the AAB/APK)

Prereqs: Node 18+, JDK 17+, Android SDK (build-tools 35, platform 35,
NDK 26.1.10909125).

```bash
npm install
npx expo prebuild --platform android      # regenerates android/
# place the keystore + set these in ~/.gradle/gradle.properties:
#   BJT_UPLOAD_STORE_FILE=bjt-pro-upload-key.keystore
#   BJT_UPLOAD_KEY_ALIAS=bjt-pro
#   BJT_UPLOAD_STORE_PASSWORD=********
#   BJT_UPLOAD_KEY_PASSWORD=********
cp credentials/bjt-pro-upload-key.keystore android/app/

cd android
./gradlew :app:bundleRelease     # -> app/build/outputs/bundle/release/app-release.aab
./gradlew :app:assembleRelease   # -> app/build/outputs/apk/release/app-release.apk
```

> `android/` and `ios/` are gitignored — they are regenerated by
> `expo prebuild` (Continuous Native Generation). The keystore credentials
> live outside the repo.

## 6. Building / submitting via EAS (alternative, recommended for CI)

EAS Build runs the build in Expo's cloud and manages signing for you.

```bash
npm i -g eas-cli
eas login
eas init                       # writes a real projectId into app.json
eas credentials                # import the existing keystore (or let EAS create one)
eas build -p android --profile production    # produces an AAB
eas submit -p android --latest               # uploads to Play (needs play-service-account.json)
```

For `eas submit`, create a Google Play **service account** JSON, grant it
release permissions in the Play Console, and save it as
`play-service-account.json` (already gitignored; path is set in `eas.json`).

> Replace the placeholder `projectId` (`00000000-…`) in `app.json` — `eas init`
> sets the real one. Bump `android.versionCode` in `app.json` for every release
> (or rely on `autoIncrement` in `eas.json`).

---

## 7. Version bumps for future releases

In `app.json`:
- `expo.version` → user-facing (e.g. `1.0.1`)
- `expo.android.versionCode` → integer, **must increase** every Play upload
- `expo.ios.buildNumber` → for iOS
